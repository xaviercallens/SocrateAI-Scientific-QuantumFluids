# Comparator setup (D6)

Goal: machine-check that each listed theorem in `QuantumFluidsShell`, `MadelungSplit`, `Duality`
states exactly what the generated challenge states, uses only `propext`, `Quot.sound`,
`Classical.choice`, and is accepted by the Lean kernel and by nanoda (second kernel). This closes
the F-NAME gap (statement equivalence) that the Lean audit alone does not.

## State (2026-09-19)
- Challenges generated by `scripts/make_comparator_challenges.py`: 11 + 5 + 9 theorems. Each challenge
  file compiles with 0 errors and exactly one `sorry` warning per listed theorem (checked with the
  v4.34.0-rc2 Mathlib build).
- Tools NOT yet installed. The root disk has ~7 GB free, so they go on the large disk.
- `lean_src/lakefile.lean` registers `ComparatorChallenges` as a non-default library. That lakefile
  edit has not been through `lake` (no manifest regeneration yet); check it on first `lake build`.

## Install
1. One privileged step, by the owner: make a user-owned directory on the large disk, e.g.
   `sudo install -d -o xavkal -g xavkal <mount>/xavkal-tools`.
   (`/dev/sda3`, 773 GB free, mounts under `/media/xavkal/3ada43de-...` but is a root-owned old system
   tree; any directory there needs sudo once.)
2. `TOOLS=<mount>/xavkal-tools bash scripts/install_comparator_tools.sh`
   builds Go (for landrun only), `landrun` (main), `lean4export` and `comparator` (tag v4.34.0-rc2),
   `nanoda_bin`. It never uses sudo and refuses a `TOOLS` on the root filesystem.
3. `export PATH=$TOOLS/bin:$PATH`

## Run (from `lean_src`, after `lake update` has produced a manifest)
```
python3 ../scripts/make_comparator_challenges.py
systemd-run --property=RestrictAddressFamilies=~AF_UNIX --user --pty -E PATH="$PATH" \
  --working-directory $(pwd) -- bash -c 'lake env comparator ComparatorChallenges/QuantumFluidsShell.json'
```
(repeat for `MadelungSplit.json`, `Duality.json`). Do NOT compile a Solution file before running
Comparator (its README: that can compromise the challenge). Do not run as a privileged user.

## Trust notes
- Generated challenges are the trusted step: review `ComparatorChallenges/*.lean` once.
- A Comparator pass says the solution proves the challenge's statement, not that the statement is
  the right physics. Statement adequacy remains a human audit (LeanMaster's 4th criterion).
